# 模型标注演示

在 Qt 的“运行设置”中勾选“模型标注演示（使用模型位置）”，保存后停止并重新启动
后台。平台中选择“模型标注演示”查看投影框。取消勾选后恢复原有 YOLO 设置。
演示模式不加载 YOLO 权重，不启动自动行驶。
后台就绪后，可用 Qt 顶部“演示视点”菜单切换到起点病害或异物位置；
起点 XJ2 对应裂缝，Odin1 可观察前方渗漏水。这是仿真视点
跳转，不是自主导航。切换前应停止另外启动的速度指令发布器。

依赖：ROS 工作空间重新编译后，系统 Python 需要 `pycollada`、`trimesh`、`embreex`。
Embree 用于加速全隧道的遮挡射线计算，避免普通射线算法的大量临时内存。运行：

```bash
python3 -m pip install --user 'pycollada>=0.7,<1' 'trimesh>=4.5,<5' 'embreex>=2,<5'
```

## 数据来源

- 读取当前 `subway_tunnel_v2.dae` 的场景层级和网格变换，单位为米、Z 轴向上。
- 对象 `6` 是起点 XJ2 视野中的裂缝，对应 `crack_01`（用户于 2026-09-10 确认）。
- 对象 `7`、`8`、`9` 对应三处渗漏水，保留编号 `leak_02`、`leak_03`、`leak_04`。
  裂缝与渗漏共用 `mat_0` 系列材质，类别按对象语义指定，不能仅由材质推断。
  当前使用这些对象的材质面，区域轮廓和投影框的贴合程度仍需逐处复核。
- `板手` 对象对应异物演示区域。
- 对象 `5` 的 `mat_9` 材质面对应 Pitch 中的管片破损掉块，编号 `segment_damage_01`。
- `W型弹条.008`、`平垫圈 GB_T 97.1 42.008`、`螺栓 GB_T 5782 M42 x 160.008`
  合并为 `fastener_loose_01`，对应 XJ3 中确认的扣件松动歪斜；三个部件只生成一个病害编号。
- 异物编号为 `foreign_01`。更换模型或编辑语义后需复核映射。
- XJ4 确认的扣件缺失位于 X≈21.31、Y≈0.854 米。以 `铁垫板.035` 外侧
  （全部顶点 Y≥0.79 米）的暴露安装面作为 `fastener_missing_01`；缺失部件本身
  没有可投影网格，框选空安装位，不包含钢轨内侧的完整扣件。该安装位只记一条坐标。
- 三维参考点选自区域表面；它不是视觉估计值，也不一定是整片病害的几何中心。
- XJ4 的扣件断裂对应对象 `2`，位于 X≈16.51、Y≈0.65 米，编号
  `fastener_broken_01`。只选断裂弹条本体，钢轨另一侧的正常 `W型弹条.028`
  不纳入该区域；弹条上的多个断口仍属于同一处病害。
- XJ2 的管线支架松脱对应 X≈10.8 米的下部管夹，编号 `bracket_loose_01`。
  合并 `细圆管连接件.004`、`六角螺栓 GB_T 5780 M36 x 140.027`、
  `平垫圈 GB_T 97.1 36.069` 和 `螺母 GB_T 6170 M36.029`；该螺母比相邻正常
  支架对应螺母下移约 4 厘米。只标注这组管夹与紧固件，不包含整条管道。

## 投影与记录

使用本项目 Gazebo 差速插件的 `/wheel/odom_raw` 世界位姿，以及图像时刻的
`base_footprint -> camera_optical_frame` 变换。它与 EKF 发布的相对 `odom` 分开处理。
使用相机 `CameraInfo` 投影表面采样点；仅显示正深度、视野内、十二米以内且通过静态
隧道视觉网格射线遮挡检查的区域。边缘框来自可见采样点，会有采样误差。
每个区域按表面积均匀采样 384 个点，至少 10% 的点同时满足上述条件才允许画框和
发布事件。只剩视野边缘或遮挡缝隙中的小碎片时不确认该区域；完整病害进入视野后
再显示。该门槛会延后部分遮挡病害的显示，不代表二维识别置信度，也不能替代投影标定。
距离上限由 `max_distance_m` 控制，可在线调整。原八米上限会漏掉车辆 X≈7.91 米时
Pitch 左下方可见的 `leak_04`（距相机约 10.4～11.4 米）；十二米上限覆盖此视角，
不改变真实深度定位节点的测距范围。

遮挡检查覆盖隧道 DAE 中的墙面、轨道、支架和扳手；不包括另外动态生成的障碍物或
机器人自身。该模式仅适用于当前静态演示场景，不能作为通用可见性验证器。

图像发布到 `/model_annotation/<camera>/image/compressed`，事件发布到
`/model_annotation/defect_events`，不会发布到 YOLO 检测话题。
同一次巡检中同一区域始终使用 `model-demo:<site_id>`，多相机观测更新同一条记录。

RViz 默认配置中的 `Defect Coordinates` 订阅 `/inspection/defect_markers`。
平台从当前巡检报告的去重记录生成红色球点：同一病害一条坐标、一个红点；
只有二维检测、没有三维坐标的记录不画点。红点保留已经记录的病害，离开相机视野
不会立即消失。消息使用 Reliable / Transient Local，暂停或稍后打开 RViz 也可读取
最近一次完整标记列表。首次打开 RViz 若仿真已暂停，还需恢复仿真以接收动态 TF，
待红点显示后再暂停；已接收的红点不会因暂停被清除。

模型参考点以 `model_annotation_world` 显示坐标系接入 `odom`；投影节点根据同一时刻
的 Gazebo 世界位姿和 EKF 变换计算二者关系，不假设世界坐标等于里程计坐标。
该显示坐标系不修改导航的 TF 父子关系。红点是独立标记图层，不是把原始点云染红。

默认数据库为 `~/.local/share/metro-inspection/model-demo.sqlite3`，与正常识别数据库
分开。界面和打印报告标注“模型标注演示”，不提供 YOLO 置信度，也不计入三维估计
完成数。位置来源为 `model_reference`、坐标系为 `world`；环号仍按当前仿真参数换算。
这些记录不能用于计算独立检测精确率、召回率或三维定位误差。

2026-09-10 修正了将对象 `6` 误归为渗漏水的类别映射。修改后需停止并重新启动后台，
在新巡检会话中查看结果。旧会话里的 `model-demo:leak_01` 是修正前的错误分类记录，
不会因代码修改自动更正，不应作为正确类别的验收数据。

同日依据用户停车截图及 Blender 参考图片补入管片破损掉块和扣件松动歪斜映射。
当前映射共十处：三处渗漏水、一处裂缝、一处管片破损、一组松动扣件、一处扣件缺失、一处扣件断裂、一处管线支架松脱、一件异物。
这不是全隧道全部病害类别的覆盖验收。新增映射的实时投影仍需验证；停车对照中
Pitch 候选面的离线投影存在偏差，尚不能宣称框选准确。

## 命令行入口

```bash
source /opt/ros/humble/setup.bash
source ros_ws/install/setup.bash
ros2 launch metro_bringup inspection_platform.launch.py model_demo:=true
```

## 本机验证

2026-09-09：相关模块 75 项测试通过。Gazebo 实测 12 路原始及演示图像在线；
渗漏区域在 XJ2、Odin1 可见，扳手在 XJ3 可见（机器人 X=26 米）。往返切换后，
148 次事件更新仍为三条区域记录。桌面 1440 像素及手机 390 像素视口通过页面检查。

退出本次测试时，模型投影节点正常退出，已有 `cmd_vel_watchdog.py` 出现一次
ROS context 关闭异常日志，Gazebo 使用超时 SIGTERM 退出。该模式的验证不代表
这些已有退出问题已经解决，也没有替代长时间稳定性测试。
